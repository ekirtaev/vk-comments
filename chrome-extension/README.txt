VK Comments 0.4.1 — Google Chrome

Расширение собирает комментарии из открытого поста VK, догружает распознанные
порции и ответы, сохраняет XLSX, CSV и JSON. Для сбора со страницы не нужны
Python, Node.js, API-токен или установка отдельной программы.

УСТАНОВКА
1. Распакуйте архив в постоянную папку. Не удаляйте её после установки.
2. В адресной строке браузера введите chrome://extensions и нажмите Enter.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение».
5. Выберите папку chrome-extension, внутри которой лежит manifest.json.
6. Найдите VK Comments через значок пазла на панели браузера и закрепите его
   или включите показ на панели инструментов.

ИСПОЛЬЗОВАНИЕ
1. Откройте отдельную страницу нужного поста или видео, например:
   https://vk.com/wall-114057117_161253
   https://vkvideo.ru/video-110135406_456244277
2. Войдите в VK обычным способом и откройте комментарии.
3. Если доступны настройки показа, включите все комментарии и хронологический
   порядок. Раскройте одну ветку ответов.
4. Нажмите значок расширения, затем Start.
5. Дождитесь остановки сбора или нажмите Стоп. Счётчик показывает число
   уникальных найденных комментариев. Повторные ID объединяются.
6. Скачайте XLSX или CSV. Также скачайте «Данные и отчёт JSON» для проверки.

Окно расширения можно закрывать: сбор продолжится в открытой вкладке поста.
До скачивания нельзя закрывать/обновлять вкладку или переходить на другой пост.
Данные хранятся в памяти вкладки; после её закрытия они будут потеряны.
Повторный Start очищает предыдущий сбор. Сначала скачайте старый результат.

ЕСЛИ ПОЛУЧЕНО 0 ИЛИ unsupported_markup
1. Убедитесь, что комментарии видны на странице.
2. В расширении нажмите «Выбрать комментарий для диагностики».
3. Щёлкните по тексту комментария на странице.
4. Откройте расширение снова и нажмите «Скачать диагностику».
5. Просмотрите VK_markup_diagnostics.json перед передачей разработчику:
   файл содержит выбранные фрагменты комментариев и сведения о разметке.
   Cookies, токены, поля форм и скрипты в диагностику не включаются.

ОБНОВЛЕНИЕ
1. Сохраните текущую выгрузку.
2. Замените файлы в установленной папке chrome-extension.
3. На chrome://extensions нажмите кнопку обновления расширения.
4. Перезагрузите страницу VK, чтобы загрузился новый сборщик.

ОГРАНИЧЕНИЯ И ПОЛНОТА
Остановка no_progress означает, что после восьми ожиданий новых ID нет.
Это не доказывает, что получены все комментарии. Сравнивайте результат со
счётчиком VK, проверяйте старые комментарии, длинные ветки и повторный сбор.
Современная разметка распознаётся по comment-text и собственной ссылке reply=ID.
Карточки без текста или ссылки могут остаться нераспознанными. Удалённые,
закрытые и недоступные аккаунту комментарии восстановить нельзя.
Неизвестные поля остаются пустыми. Пустой is_reply означает, что тип неизвестен.
Один комментарий = одна строка. JSON содержит полный извлечённый текст;
в XLSX предел одной ячейки — 32767 символов. CSV — UTF-8, разделитель «;».
Текст CSV, похожий на формулу, получает защитный апостроф; оригинал в JSON.
Пользователь сообщил об успешном сборе в Chrome; полнота не доказана.

ДОПОЛНИТЕЛЬНЫЙ API-РЕЖИМ
Внизу окна есть «Дополнительный API-режим». Он требует отдельный токен VK API.
Откройте режим, вставьте URL и токен, нажмите «Проверить доступ», затем Start.
Оставьте вкладку API открытой до скачивания. Токен хранится в памяти,
передаётся только api.vk.com и не включается в выгрузку.
Разрешение расширения на api.vk.com используется только этим режимом.

VK ВИДЕО
Поддержаны адреса videoOWNER_ID на vkvideo.ru и vk.com. Откройте область
комментариев под видео перед Start. Ссылки reply/comment/comment_id
распознаются по карточке с comment-text. На живой видеостранице эта версия
ещё не проверена. Если записей 0, выберите комментарий для диагностики
и передайте VK_markup_diagnostics.json разработчику. API-режим предназначен
для постов wall; адаптация видео касается сбора из страницы.

Версия 0.4.1 распознаёт карточки VK Видео с data-testid=comment
и числовым id, в том числе без ссылок на комментарии. Имя читается
из comment-owner. Относительная дата сохраняется в date_display;
точная date остаётся пустой, если её нет в разметке.
